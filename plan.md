# API Scanner — Plan

## 1. Approach Overview

A Node.js script that wraps a Playwright browser session and does two things simultaneously:

1. Uses Playwright's native `recordHar` option on the browser context to write a complete HAR file capturing every request/response during the journey.
2. Attaches `page.on('request')` / `page.on('response')` listeners to filter and log only API traffic in real time for console feedback.

After the journey ends, a post-processing step reads the raw HAR and produces:
- **The HAR itself** — usable directly for replay or conversion.
- **OpenAPI 3.0 spec** — generated via `har-to-openapi`, consumable by schemathesis.
- **StepCI workflow YAML** — generated by a small custom transformer, ready to run as regression tests.

---

## 2. Tool and Library Choices

| Tool | Why |
|------|-----|
| **Playwright `recordHar`** | Official, reliable, captures everything including cross-origin requests. Outputs standard HAR 1.2. No proxy or extra process needed. `urlFilter` option narrows capture to API traffic. |
| **`har-to-openapi` (npm)** | Handles the hard parts: path parameter detection, request/response body schema inference, grouping multiple calls to the same endpoint. Avoids writing schema inference from scratch. |
| **Custom StepCI transformer** | StepCI has no HAR importer. The YAML structure is simple enough (~80 lines) to transform directly. No extra dependency needed. |
| **TypeScript / Node.js** | Consistent with Playwright's ecosystem; types available for HAR, OpenAPI, and StepCI structures. |

## 3. Folder and File Structure

```
api-scanner/
├── src/
│   ├── capture.ts                  # Main entry: launches Playwright, records HAR, orchestrates transforms
│   ├── transform/
│   │   ├── toOpenApi.ts            # Wraps har-to-openapi → openapi.yaml + openapi.json
│   │   └── toStepci.ts             # Walks HAR entries → stepci-workflow.yaml
│   └── utils/
│       └── harFilter.ts            # Filters HAR to API-only entries (xhr/fetch + URL filter)
├── captures/                       # Created at runtime, one subfolder per run
│   └── <timestamp>-<slug>/
│       ├── raw.har                 # Full unmodified HAR from Playwright
│       ├── openapi.yaml            # Generated OpenAPI 3.0 spec
│       ├── openapi.json            # Same spec as JSON
│       └── stepci-workflow.yaml    # StepCI runbook
├── package.json
├── tsconfig.json
└── plan.md
```

Each run gets its own `<timestamp>-<slug>` subfolder (e.g. `2026-04-24T10-30-00-checkout-flow`) so multiple journeys accumulate without overwriting.

## 4. Output Formats

### 4a. Raw HAR (`raw.har`)
Standard HAR 1.2 JSON. Each entry contains `request` (method, URL, headers, body, queryString) and `response` (status, headers, content). Always preserved intact — source of truth for downstream transforms and Playwright replay mocking.

### 4b. OpenAPI Spec (`openapi.yaml` / `openapi.json`)
Generated by `har-to-openapi`. Groups entries by URL path pattern, infers path parameters (e.g. `/users/123` → `/users/{id}`), and builds `paths` objects with request/response schemas.

Run schemathesis against it:
```bash
schemathesis run ./captures/<run>/openapi.yaml --url https://api.example.com --checks all
```

Notes:
- `servers` field is set automatically from HAR origins.
- `guessAuthenticationHeaders: true` marks auth headers as security schemes rather than hard-coding values.
- Response bodies become `examples` in the spec.

### 4c. StepCI Workflow (`stepci-workflow.yaml`)
Custom transformer output:

```yaml
version: "1.1"
name: "Captured journey - checkout-flow"
tests:
  captured_api_calls:
    steps:
      - name: "POST /api/cart/items"
        http:
          url: https://api.example.com/api/cart/items
          method: POST
          headers:
            Content-Type: application/json
            Authorization: Bearer <REDACTED>
          json:
            productId: "abc123"
            quantity: 2
          check:
            status: 200
```

Transformation rules:
- Each HAR entry matching the API filter → one step.
- `name` = `"{METHOD} {pathname}"`.
- Authorization values → `<REDACTED>` (user substitutes real values or `${{secrets.TOKEN}}` for CI).
- JSON bodies → `json:`, other bodies → `body:`.
- `check.status` = observed status code (regression baseline).
- Top-level response JSON keys → `jsonpath` presence checks (validates shape, not exact values).

Run with:
```bash
stepci run ./captures/<run>/stepci-workflow.yaml
```

## 5. Implementation Steps

1. **Project scaffold** — `package.json`, `tsconfig.json`, install deps: `playwright`, `har-to-openapi`, `js-yaml`, `typescript`, `ts-node`, `@types/node`.

2. **`capture.ts`** — CLI entry point:
   - Accept `--url <start-url>`, `--out <name>`, `--filter <glob>` (default: `**/api/**`).
   - Launch Chromium (`headless: false` for manual journeys; `--script <file>` for automated).
   - Create context with `recordHar: { path, urlFilter, content: 'body' }`.
   - Attach `page.on('request'/'response')` for console logging.
   - Navigate to `--url`, wait for user to press Enter (or script to finish).
   - `await context.close()` — flushes HAR to disk.

3. **`harFilter.ts`** — Read raw HAR, keep only entries where resource type is `xhr`/`fetch` and URL matches the filter glob. Write filtered copy (raw is kept intact).

4. **`toOpenApi.ts`** — Call `generateSpec(filteredHar, { guessAuthenticationHeaders: true })`, write `openapi.json` and `openapi.yaml`.

5. **`toStepci.ts`** — Walk `filteredHar.log.entries`, build step objects, assemble workflow, serialize with `js-yaml`, write `stepci-workflow.yaml`.

6. **Orchestration** — `main()` calls steps 2–5 in sequence, then prints output file paths.

7. **npm scripts** — `"capture": "ts-node src/capture.ts"` in `package.json`.

## 6. What You Need to Run It

**Prerequisites:**
```bash
node --version   # 18+
python --version # 3.8+ (for schemathesis)
npx playwright install chromium  # first time only
```

**Install project deps:**
```bash
npm install
```

**Install schemathesis:**
```bash
pip install schemathesis
# or: pipx install schemathesis
```

**Install StepCI:**
```bash
npm install -g stepci
```

**Capture a journey:**
```bash
npm run capture -- --url https://example.com --out my-journey --filter "**/api/**"
# browser opens → perform the journey → press Enter → outputs written to captures/my-journey/
```

**Fuzz with schemathesis:**
```bash
schemathesis run ./captures/my-journey/openapi.yaml --url https://example.com --checks all
```

**Run StepCI regression tests:**
```bash
stepci run ./captures/my-journey/stepci-workflow.yaml
```

**Optionally replay HAR as a mock in Playwright:**
```typescript
await context.routeFromHAR('./captures/my-journey/raw.har', { notFound: 'fallback' });
```

## 7. Design Decisions

- **`recordHar` over manual accumulation** — more reliable, records cross-origin requests, standard format.
- **Raw HAR always preserved** — filtered copy drives transforms, raw stays for debugging and replay.
- **`har-to-openapi` over DIY** — handles path parameter detection and schema inference which would dominate implementation effort.
- **StepCI checks use observed status codes** — immediately runnable regression baselines without manual tuning.
- **Auth headers redacted in StepCI output** — safe default; user substitutes real values before CI use.
